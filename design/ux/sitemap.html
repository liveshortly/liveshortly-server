C What this map surfaces Behavior implied by the code, not by intent
† 1 — Replay / Story / Compose are unreachable by anon
All three fetch getSession(id) client-side and would happily render for any session the API allows anonymous reads on (visibility=open), same as /session/[id]. But because they aren't in AuthGate's isPublicRoute allowlist, an anon visitor hitting /story/abc gets the marketing <Landing/> instead — a dead end, not a sign-in prompt. Likely fine if these are meant to stay owner-only for now, but worth a deliberate call rather than an accident of the allowlist.
† 2 — "/" means two different components
app/page.tsx always renders <Feed/>, but AuthGate intercepts anon traffic before it gets there and substitutes <Landing/> — which itself embeds a feed. Two independent "feed" implementations exist for the same URL depending on auth state.
† 3 — Admin pages flash before redirecting
useAdminGuard is client-only: a non-admin briefly mounts /admin in "checking" phase before the redirect fires. No SSR/middleware gate — acceptable since the API independently 403s, but the route itself is not instant for a non-admin who bookmarks it.

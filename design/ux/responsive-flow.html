Desktop vs. Mobile — Session Viewer

/session/[id] is the one screen with two fully independent renderers for the same event stream — EventStream (desktop) and MobileEventFeed (mobile) — switched by CSS, not JS, so neither remounts on resize. This is also where nearly all of the last five commits landed, so it's the most likely place for the two layouts to drift out of sync.

⚠ Two thresholds, 40px apart, controlling one screen
At a viewport between 821–860px the sidebar is a full permanent panel (desktop mode) while the event feed below has already switched to the mobile renderer + gear button — a real, reachable in-between state, not just a rounding accident. Worth confirming that's intentional (sidebar and feed are different concerns) rather than two breakpoints that were meant to be the same number.

D Why CSS, not JS, decides which renders
Both mount, always
.desktop-feed-wrap + .mobile-feed-wrap
Both components render on every load; the media query flips display. No remount on resize/rotate means no lost scroll position, no re-subscribing the SSE-driven state.
A documented past bug
Plain class rules only — never inline styles
A code comment on .session-actions flags this explicitly: an inline style on the element would beat the mobile media query no matter its specificity, and that caused a real regression once. Any future variant of this show/hide pattern should follow the same rule.

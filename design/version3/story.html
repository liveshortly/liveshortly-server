Chapter 1 +00m 00s into session
Let's build the auth middleware. Go API needs JWT on every route — Bearer for CLI, cookie for web.

We'll start with a single identity resolution layer so handlers never have to care which auth path was used.

The Authn middleware extracts a token from either Authorization: Bearer <jwt> (CLI) or the ls_session HttpOnly cookie (web), verifies it, and injects the resolved Identity into the request context. Downstream handlers call one auth.From(ctx) helper.

Key Design Decision
Both Bearer and cookie tokens share the same JWT format and verification logic — only the extraction path differs, so the API needs one auth stack, not two. The typ claim ("web" vs "access") distinguishes them post-verification if a handler needs to know.

Chapter 2 +12m 40s into session
Now the database migration — I need users and auth_sessions tables before the OAuth callback can work.

users stores the Google-sourced identity with a unique constraint on google_sub for upsert-on-login. auth_sessions stores CLI refresh tokens as a hash with expiry and a soft-revoke flag, so a compromised device grant can be killed without rotating the signing secret.

Why store the token hash rather than the full token? Couldn't you just check expiry in the JWT itself?
Claude responded (via CLI injection)
JWTs are stateless, so expiry alone can't revoke a compromised token early. Storing the hash gives us a revoke-able allowlist — one extra DB lookup per refresh, worth it for security.

Chapter 3 +38m 55s into session
Last piece — the CLI device flow. The hooks need an access token without a browser. Poll-based: start → poll → done.

The CLI calls POST /auth/device/start, which creates a pending grant in Redis with a short TTL and returns a device_code plus a URL to open in a browser. The CLI polls POST /auth/device/poll until approved, then writes the resulting token pair to ~/.liveshortly/credentials.json.

The Full Auth Architecture
Two token types, one JWT secret: web (24h, cookie) and access (1h, Bearer) — both resolved by the same Authn middleware. Device grants are ephemeral Redis keys; refresh tokens live in Postgres with soft-revoke. The CLI auto-refreshes and only needs ls login again after 30 days.

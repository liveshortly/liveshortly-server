"Let's build the auth middleware. Bearer for CLI, cookie for web."

We start with a single identity resolution layer so handlers never care which auth path was used.

The Authn middleware extracts a token from either the header or cookie, verifies it, and injects the resolved Identity into the request context.

Why store the token hash rather than the full token?
JWTs are stateless, so expiry alone can't revoke a compromised token early. The hash gives us a revoke-able allowlist.
